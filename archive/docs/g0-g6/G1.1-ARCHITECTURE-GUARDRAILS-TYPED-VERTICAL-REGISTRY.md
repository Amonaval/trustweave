# G1.1 — Architecture Guardrails + Typed Vertical Registry

**Date:** 2026-08-25  
**Status:** IMPLEMENTED IN SOURCE / NON-USER-FACING / BUILD VERIFY ENVIRONMENT-LIMITED  
**Parent:** G0 Trusted Network Architecture Classification & Extraction Blueprint

## Objective

Introduce the first physical capability-tree seam without changing Family behavior, Family RPCs, Family tables, navigation, feature rollout, or user journeys.

## Implemented

### 1. Core vertical contract

`core/verticals/contracts.ts`

Defines only typed composition facts:
- `NetworkVerticalKind = family | alumni`;
- capability IDs;
- navigation descriptor shape;
- legacy network labels used only as compatibility defaults;
- `VerticalDefinition`.

The contract deliberately does **not** contain database schema, relationship meaning, authorization rules, identity matching policy, conflict-resolution policy, or arbitrary workflow JSON.

### 2. Explicit Family vertical

`verticals/family/definition.ts`

Family is registered as the active/default production vertical. Its current setup labels remain exactly:
- Member / Members;
- Generation / Generations;
- Parent / Child / Spouse.

Kinship is explicitly selected through `domain.kinship`; it is not redefined as a generic graph relationship model.

### 3. Alumni skeleton

`verticals/alumni/definition.ts`

Alumni is registered only as a **skeleton**. It declares `domain.institutional-membership` rather than `domain.kinship`.

There is intentionally:
- no Alumni product route;
- no Alumni setup option;
- no Alumni database model;
- no reuse of Family RPCs as Alumni behavior;
- no claim that Senior/Junior/Classmate labels are an Alumni domain model.

### 4. App-shell registry

`app-shell/vertical-registry.ts`

Composition happens above core and explicit verticals. The registry:
- imports Family and Alumni definitions;
- rejects duplicate vertical registration;
- keeps `family` as the default;
- exposes typed lookup and runtime kind validation.

This preserves the dependency direction:

`Vertical → Domain/Capability → Core`, with app-shell composition above them.

### 5. Runtime compatibility bridge

`lib/network.ts`

`NetworkSettings` now has optional `vertical_kind` and `getNetworkConfig()` resolves a typed runtime vertical.

Compatibility behavior:
- existing persisted rows with no `vertical_kind` remain valid;
- existing `network_template = family` resolves to `family`;
- absent/unknown legacy template defaults to Family, matching prior runtime behavior;
- legacy `network_template = alumni` can resolve to the Alumni skeleton but does not activate an Alumni product.

No database migration was added in G1.1. Persistence of `vertical_kind` should be additive only when the next concrete consumer needs it.

### 6. Family setup wired through the registry

`components/SetupScreen.tsx`

Family creation now obtains its existing label defaults from `getVerticalDefinition("family")` and passes `vertical_kind: family` in the in-memory settings object.

The visible Family setup flow, copy, labels, mode selection and backend calls remain unchanged.

### 7. Architecture source gate

`scripts/g1-1-architecture-gate.mjs`

The gate verifies:
- required G1.1 files exist;
- Family + Alumni are typed registry kinds;
- Family is active/default;
- Alumni remains skeleton;
- duplicate-registration guard exists;
- Family setup actually uses the registry;
- core/capability/domain-layer code cannot import explicit vertical implementations;
- Family and Alumni definitions cannot import each other.

`package.json` adds `validate:g1.1`.

### Environment limitation

A full repository `tsc --noEmit` / `next build` could not be certified in this execution environment because the uploaded ZIP contains no `node_modules` and dependency installation did not complete before the environment reset. Initial TypeScript errors were dependency-resolution errors (`react`, `next`, `lucide-react`, Supabase types), not G1.1 type errors.

Therefore G1.1 is **source-implemented and regression-gated**, but full production build verification should be rerun in the normal project environment/CI before deployment.
