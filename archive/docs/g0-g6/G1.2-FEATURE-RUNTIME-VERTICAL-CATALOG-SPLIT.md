# G1.2 — Feature Runtime / Vertical Catalog Split

**Date:** 2026-08-25  
**Status:** IMPLEMENTED IN SOURCE / CLOSED AS NON-USER-FACING ARCHITECTURE MISSION / FULL NEXT BUILD ENVIRONMENT-LIMITED

## Objective

Separate reusable feature rollout/evaluation mechanics from Family-specific feature definitions while preserving the existing Family application contract exactly.

G1.2 is an extraction mission, not a feature redesign. It intentionally does **not** rename database keys/RPCs, change rollout states, change Family navigation, expose Alumni, or generalize kinship/S3-A1.

## Classification

### CORE — generic feature runtime

Moved to `core/features/`:

- `LaunchState` runtime vocabulary: hidden / test / pilot / released;
- generic typed feature definition/catalog contracts;
- effective-feature state shape;
- feature index creation;
- default feature-map creation;
- experience/admin eligibility evaluation;
- reusable per-catalog runtime composition.

The core runtime contains no Family, Alumni, kinship, parent/child/spouse, or vertical imports.

### FAMILY VERTICAL — feature catalog

Moved to `verticals/family/features/catalog.ts`:

- all 23 existing Family feature keys;
- exact bundle membership;
- exact labels/descriptions;
- exact Simple/Connected/Explorer rank and copy;
- exact `minimumExperience` values;
- exact default rollout values.

This is now composed by `FAMILY_VERTICAL.featureCatalog`.

### ALUMNI VERTICAL — proof catalog only

`verticals/alumni/features/catalog.ts` adds a deliberately tiny hidden-by-default catalog solely to prove that the core feature runtime can serve a second vertical with different feature keys and experience semantics.

No Alumni UI, RPC, database row, Launch Control exposure, or navigation is enabled in G1.2.

## Compatibility strategy

`lib/features.ts` remains the historical Family compatibility facade. Existing consumers continue importing:

- `ExperienceLevel`
- `LaunchState`
- `FeatureBundle`
- `FeatureKey`
- `FeatureDefinition`
- `EXPERIENCE_RANK`
- `EXPERIENCE_LABELS`
- `FEATURE_REGISTRY`
- `FEATURE_BY_KEY`
- `EffectiveFeature`
- `EffectiveFeatureMap`
- `defaultFeatureMap()`
- `isFeatureAvailable()`

The facade now resolves the Family catalog through `app-shell/vertical-registry.ts` and delegates runtime behavior to `core/features/runtime.ts`.

Therefore `NetworkApp`, `FamilyAdminCenter`, `FounderLaunchConsole`, guide typing and existing remote/RPC behavior do not require a big-bang migration.

## Family behavior preservation contract

The following values are regression-locked by `validate:g1.2`:

- feature key count/order: 23, unchanged;
- bundle assignment: unchanged;
- minimum experience: unchanged;
- default launch state: unchanged;
- Simple/Connected/Explorer rank: unchanged;
- experience labels/descriptions: unchanged;
- compatibility exports from `lib/features.ts`: unchanged.

The runtime behavior was also exercised independently after TypeScript compilation:

- released features are enabled by default in normal mode;
- test/pilot/hidden features are not enabled by default;
- local/demo mode releases/enables the complete catalog;
- experience gating remains unchanged;
- admin-only features still require admin;
- the feature lookup is precomputed once rather than rebuilt on each eligibility check.

## Regression gate maintenance

Two historical source gates previously assumed the canonical feature declarations lived directly in `lib/features.ts`:

- `scripts/s2-b-source-gate.mjs`
- `scripts/s3-a1-source-gate.mjs`

They now inspect `verticals/family/features/catalog.ts`, preserving the original checks for `connect.community` and `contribute.branch_intake` rather than weakening or deleting those protections.

No migration was added. No RPC/table/feature key was renamed. Existing rows in `platform_feature_flags`, `network_feature_settings`, Playground controls, rollout audit and announcements remain compatible.
