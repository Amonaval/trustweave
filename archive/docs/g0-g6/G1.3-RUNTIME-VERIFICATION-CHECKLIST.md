# G1.3 — Quick Runtime Verification

This is intentionally a **high-level smoke check**, not a full regression cycle.

## Before checking

Apply Supabase migrations in order through:
1. `043_s3a1_distributed_family_intake.sql`
2. `044_g1_3_feature_catalog_integrity.sql`

Migration 044 does not overwrite existing rollout/Playground choices.

## 4 quick checks

1. **Existing Family still opens normally**  
   Sign in and open your current family. Home, Family, Find Family and Me should look/behave as before.

2. **Role + switching still work**  
   If you have multiple families, switch once. Owner/Admin access should remain the same and the selected family should reload normally.

3. **Re-test the issue you found**  
   Platform Owner → Launch Control → Playground → **Build family together**. Toggle OFF and ON once. It should save without `Unknown feature key`.

4. **One console glance**  
   Reload once and confirm there is no feature-registry, membership, active-network or vertical-registry error in the browser console.

If a feature says **Database update required**, the frontend is newer than the deployed feature registry. Apply the pending Supabase migrations rather than forcing the toggle.
