# G9.1-B — Organization Knowledge Bootstrap

## Mission
Turn authorized organization knowledge into evidence-backed candidate expertise, ownership, dependency and architectural-decision assertions without allowing AI to write canonical graph truth directly.

## Decoupling
- G9 deterministic intelligence is unchanged.
- Knowledge Hub standalone query/ingestion/Electron/API flows are unchanged.
- New Knowledge Hub bridge modules use separate network/corpus namespaces.
- Network OS receives evidence/candidates through new governed RPCs only.
- Human admin verification is required before expertise/relationship candidates commit to canonical graph structures.

## Candidate lifecycle
Authorized source → network-scoped corpus/evidence → targeted extraction → candidate assertion → admin review → verified graph/evidence truth or rejection.

## First supported fact types
- expertise → `skill` affiliation
- ownership → `owns` relationship
- dependency → `depends_on` relationship
- architectural decision → verified evidence assertion (not forced into graph relationship model)

## Safety
Candidate inserts require evidence IDs belonging to the active network. Review functions resolve against the active network. Unsupported predicates are rejected. Existing evidence and review history are preserved.
