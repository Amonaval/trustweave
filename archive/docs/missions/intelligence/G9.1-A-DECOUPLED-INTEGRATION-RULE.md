# G9.1-A Decoupled Integration Rule

Permanent rule for Network OS ↔ Knowledge Hub work:

1. Prefer new bridge modules/files over edits to either existing runtime.
2. Existing Network OS and Knowledge Hub must remain independently runnable.
3. Modify existing code only when a bridge cannot be implemented safely otherwise; keep such edits minimal and backward compatible.
4. Network OS remains canonical graph truth. AI/RAG output enters as evidence-backed candidates, never silent graph mutation.
5. Authentication, network tenancy and authorization are supplied/enforced by Network OS boundaries; client-supplied identity is never trusted as authorization.
6. Knowledge Hub internals may be reused behind adapters but its Electron UI, local filesystem assumptions and current API are not imported into Network OS.
7. Shared extraction is earned incrementally after the bridge contract proves stable; do not refactor both products merely to create theoretical reuse.
8. Every integration batch must run the previous Network OS validation chain to prove existing verticals remain unaffected.
