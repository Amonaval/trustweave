# G9.1-D — Organizational Knowledge Risk Loop

## Outcome
G9.1-D converts verified Organization graph structure, evidence health, and question outcomes into proactive risk signals. It does not use an LLM to assign risk scores and it does not mutate canonical graph truth.

## Signals
- Key-person / ownership concentration.
- Missing ownership on entities that already have verified dependencies.
- Dependency-critical entities with multiple inbound `depends_on` links.
- Repeated low-confidence or zero-evidence Organization questions.
- Stale network-visible knowledge evidence (>365 days).
- Candidate assertions already marked `conflicted`.

## Runtime boundary
- G9 deterministic intelligence remains unchanged.
- G9.1-C emits a small governed query outcome signal after a question completes.
- Supabase is the shared signal store and tenant boundary.
- Risk calculation is deterministic in `capabilities/organization-risk/engine.ts`.
- The risk panel is visible only to Organization admins in the current product wiring.
- Knowledge Hub/Ollama are not required to keep the risk panel running after evidence/candidates have been ingested.

## Gap-to-action
Each risk signal includes a concrete next action such as assigning an owner, verifying backup expertise, refreshing stale evidence, routing a repeated question to an expert, or resolving conflicting assertions.

## Decoupling
No Knowledge Hub runtime file is modified by G9.1-D. The mission builds on Supabase evidence/candidate state and Network OS query signals, preserving both standalone products.
