# P4.1 — Foundation, Trust & Adoption

This release is built from the P3 source baseline and keeps existing P3 functionality intact.

## Added

### Trust
- Role-aware member projection via `get_visible_family_members()`; regular members do not receive phone/email from `family_members`.
- Database relationship trigger preventing self-links, invalid parent generations and parent/child cycles.
- Canonical spouse uniqueness.
- Client-side import/network integrity validation and duplicate identity warnings.
- Generalized `change_requests` and capability foundation.
- Audit event RPC and governance UI.

### Adoption
- `profile-photos` Supabase Storage bucket.
- JPG/PNG/WebP upload validation, 5 MB maximum.
- Profile photo preview in profile submission flow.
- Admin-created, single-use, expiring invitation links.
- `/invite/[token]` onboarding route.
- Invitation acceptance links an authenticated account to the existing hierarchy member.

### Architecture
- `lib/repository.ts` introduces `NetworkRepository` with shared Supabase and local implementations.
- UI data operations use the repository boundary rather than scattering Supabase/local persistence decisions through each mutation.

### Mobile
- Bottom navigation is introduced in P4.1.
- All P4 features are required to remain usable on mobile.

## Supabase migrations

For a new database, run all migrations in order.

For an existing P3 database, run:

1. `005_p4_1_governance_integrity.sql`
2. `006_p4_1_adoption.sql`

Migration 006 creates the storage bucket, storage policies, member invitation table/functions and the `profiles.member_id` claim link.

## Security notes

- Invitation tokens are only stored as SHA-256 hashes in the database.
- Invitations expire after 1–30 days and can be consumed once.
- Invitation acceptance requires authentication.
- Profile photos are community-visible by design; private contact fields remain database-protected.
- Never expose a Supabase service-role key in the browser.
