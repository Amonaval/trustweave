# P4.3 — Community, Memories & Discovery

P4.3 is built directly on the fixed P4.2 source baseline, including the P4.1 family_members privilege/RLS correction and P4.2 migration compatibility fix.

## Implemented

### Community memories
- New Community area accessible from desktop sidebar and mobile bottom navigation.
- Members can share simple memories/stories.
- Optional JPG/PNG/WebP photo upload through Supabase Storage.
- Memories can be attached to the current member profile; administrators can attach them to another member or leave them as community memories.
- Visibility: public/member/admin.
- Profile drawer displays memories attached to the selected member.
- Owners/admins can remove memories.

### Notifications
- In-app notification model with read/unread state.
- Notifications are displayed in Community > Updates.
- Change-request review creates a notification for the submitter.
- Invitation acceptance can notify the administrator who created the invitation.
- Notifications are user-scoped through security-definer RPCs.

### Discovery
- Directory search now supports:
  - name / profession / city / country text search
  - profession
  - city
  - generation
  - living / deceased status
- Existing lineage focus, relationship exploration and map discovery remain intact.
- P4.4 will move high-scale discovery server-side; P4.3 keeps the existing in-memory model for compatibility with the current app.

### Collaboration
- Existing generalized change requests remain the approval backbone.
- Review notifications are now part of the contribution loop.
- Audit logging continues to record community contributions and reviews.

### Mobile
- Community is included in bottom navigation.
- Memory cards, notification list and discovery filters are responsive.
- Mobile remains a continuous P4 requirement.

## Supabase migration

For an existing P4.2 database, run only:

`supabase/migrations/008_p4_3_community_discovery.sql`

It adds:
- `community-media` Storage bucket and policies
- `memories`
- `notifications`
- memory RPCs
- notification RPCs
- change-request review notifications
- invitation acceptance notifications

## Deployment order

Existing production database:

`001 -> 002 -> 003 -> 004 -> 005 -> 006 -> 007 -> 008`

If 001–007 are already applied, only apply `008`.

## Validation

The modified source was parsed with TypeScript after the P4.3 changes. No P4.3 JSX syntax errors remain. A complete Next.js build was not possible in the isolated environment because npm dependencies are not installed/available; run `npm install && npm run build` in the normal project environment before production deployment.
