# M3-D2 — Canonical vertical manifest

**Baseline:** `llm-push` at `f635d9ff3de1877b8976a974b15f50e69fddded8`. Source certification candidate; authenticated browser checks are deliberately batched with D1 and the following missions.

## Change

`core/verticals/kinds.ts` is the small runtime kind vocabulary and sole source for the TypeScript `NetworkVerticalKind` union. `app-shell/vertical-manifest.ts` is the single authoritative composition record for the nine current verticals: definition, feature catalog through definition, app navigation/Guide/Playground/launch composition, runtime mode and productized configuration where applicable.

`vertical-registry.ts`, `vertical-runtime.ts` and `vertical-capabilities.ts` now project from that record. The Family and Alumni identity/participation/construction adapters remain explicit; productized capability runtime entries are generated by mode rather than copied into a nine-entry map. The membership transport uses the lightweight kind vocabulary and rejects an explicitly unknown vertical. Productized config still owns extensive product text, fixtures and domain vocabulary; it is verified against the manifest rather than moved into the platform kernel. Future template proofs in `template-registry.ts` are composition recipes, not released vertical registrations.

## Fitness comparison

| Check | D0 | D2 candidate |
| --- | --- | --- |
| Authoritative vertical registration maps | Definition, app composition and capability runtime each listed nine kinds; membership transport listed them again | One manifest plus one small kind vocabulary; projections derive from the manifest; productized config retains domain data but no separate kind union. |
| Unknown kind | Some getters could return `undefined` at runtime after an unchecked cast | Manifest, definition, app and capability getters throw; transport validates explicit kind. |
| Feature/navigation mismatch | `vertical-runtime.ts` checked catalog and capability references | Manifest checks identity/status/catalog, configuration kind, duplicate navigation IDs and referenced features/capabilities at startup. |
| Adding a skeleton vertical | Several parallel maps had to be updated | Add kind, definition/composition and one manifest entry; typed manifest and tests fail until aligned. Domain-specific template/config/adapter work remains necessary where relevant. |
| Bundle | D1 production `/` and network route: 754 kB First Load JS | D2 production network route: 754 kB First Load JS; this slice does not claim lazy vertical loading (D7). |
