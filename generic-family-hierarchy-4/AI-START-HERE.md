## Working doctrine

- Think **company → user/buyer → adoption/trust → product outcome → reusable capability → vertical semantics → architecture → implementation → code**.
- Keep **one active priority**. OPEN / PARKED / documented does not mean NEXT.
- Default alpha/pilot work to roughly **20–30% of theoretical perfect effort for 70–80% of impact/learning**, except high-consequence security/privacy/data-integrity work.
- Prefer **Generic + Easy + Impactful**.
- Prefer **Adopt → Compose → Extend → Build**.
- Complete/discover/reuse existing capability before adding breadth.
- Source proof ≠ runtime proof ≠ pilot validation.
- Use the smallest targeted evidence set that proves the mission.
- Default to **1–5 coherent commits**; avoid tool-generated micro-commit history.
- Do not run broad workflows/QA/recovery programs without a concrete current risk.
- Do not apply Supabase migrations automatically.
- Do not initiate or consume anything that may create additional cost without explicit Founder warning and consent.
- Founder time is a first-class company cost; routine error relay and engineering coordination should trend toward zero.
- Documentation should become **smaller, smarter and more decision-useful**.
