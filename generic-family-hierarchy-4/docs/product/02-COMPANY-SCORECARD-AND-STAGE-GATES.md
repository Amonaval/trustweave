# TrustWeave — Company Scorecard & Stage Gates

**Status:** CANONICAL MEASUREMENT FRAMEWORK  
**Effective:** 2026-09-23

TrustWeave measures outcomes that reveal whether a real company is emerging, not vanity metrics that reward feature production.

Do not invent numbers when telemetry/evidence is unavailable. Record UNKNOWN and add measurement only when the answer can change a decision.

## Current stage

**Flagship pilot → real adoption proof**

Primary proving networks:

- **MPF Pune East** — Community / Association proving ground.
- **Majestique Marbella** — Residential / Housing Society proving ground.

Primary question:

> **Can these networks repeatedly run meaningful real-life workflows in TrustWeave with low Founder/developer assistance?**

## Scorecard dimensions

### Adoption

Track as evidence becomes available:

- active real networks;
- activated households/families/members;
- weekly/monthly returning users;
- invitation-to-activation;
- member/admin journeys completed without support;
- meaningful actions, not page views.

### Habit / return value

Examples include event RSVP, directory/profile use, posts/comments/groups, birthdays/memories, membership/renewal, Residential operations, notification/deep-link return and repeated household/admin use across weeks.

### Administrative value

Where practical measure manual follow-ups removed, spreadsheets/chat threads replaced for a real task, time spent on recurring admin work, unresolved actions surfaced, duplicate data entry reduced and onboarding effort.

### Platform leverage

Track whether requirements are solved in shared capability vs vertical-specific code, number of consumers per capability, time to launch another same-type network, per-network engineering effort, duplicate logic removed and how much of a new vertical composes existing primitives.

### Trust / quality

- tenant/privacy/security escapes: target **0**;
- data loss/corruption: target **0**;
- unresolved P0/P1 runtime blockers;
- critical journeys with runtime proof;
- regressions found by users after claimed closure;
- backup/recovery confidence appropriate to commercial stage.

### Commercial proof

Use the ladder:

> **interest → demo/pilot request → real data/network onboarding → repeated use → willingness-to-pay signal → paid pilot/customer → renewal/expansion**

Do not prematurely optimize pricing machinery ahead of this evidence.

### Founder leverage

Track Founder interventions per mission, manual error relay, Founder setup/support time per network, repeated work that should become self-service, and high-effort missions that produced little learning.

### AI value

For each serious AI capability record the real user job, TrustWeave context used, evidence/provenance, permission/action boundary, measurable improvement, operating cost and return usage.

**AI feature count is not a metric.**

## Stage gates

### Gate A — flagship ready

Move beyond readiness when MPF and Marbella have realistic/full-fidelity data, primary admin/member journeys work, critical trust/reliability blockers are closed and ordinary use does not require constant developer explanation.

### Gate B — flagship habit

Move beyond early pilot when real users return for multiple jobs, admins choose TrustWeave for recurring work, return loops are visible and requirements increasingly come from observed use.

### Gate C — repeatability

Broaden network acquisition when another same-type network can launch without custom architecture, onboarding/data import is understandable, configuration handles common variation and per-network engineering effort is falling.

### Gate D — adjacent vertical proof

School/Preschool or Business earns serious investment when flagship products remain stable, reuse is favorable, a real/design-partner problem exists, the vertical strategically stresses the platform, and the genuinely domain-specific seam is bounded.

### Gate E — commercial product

Commercialization accelerates when the product explains itself, demo/pilot path is professional, organizations show willingness to pay, support burden is manageable and trust/reliability are credible.

### Gate F — scale architecture

Scale infrastructure is authorized from measured evidence such as sustained load/latency, queue/background needs, reliability/SLA obligations, database/storage limits, operational bottlenecks or compliance requirements — not from a calendar milestone.

## 12-month aspirational portfolio

Goals, not promises or permission for shallow breadth:

- 10+ small-business networks/use cases;
- 10+ preschools/playgroups;
- 1 larger school;
- 3+ Residential networks;
- 3+ Communities/Associations;
- 300+ families;
- 5,000+ members.

If exact counts are lower but sustained usage, repeatability and willingness-to-pay are strong, the year can still be successful.

If counts are high but engagement/reuse/payment evidence is weak, it is not success.

## Weekly/monthly review questions

1. What became real that was previously only possible in source?
2. Which user behavior increased?
3. Which repeated friction appeared?
4. Which feature exists but is not discovered/used?
5. What manual work did Founder/admin/developer repeat?
6. What capability was reused across networks?
7. What complexity did we add that has not paid back?
8. What should we stop doing?
9. Did evidence change the next mission?
10. Are we closer to repeated usage, repeatability and willingness to pay?
