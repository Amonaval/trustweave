# Mission 2 — Slow Automation QA Runbook

## Purpose
Run broad real-user regression slowly enough for the Supabase Free Tier while treating unexpected database/API errors as failures even if the page does not crash.

## Prerequisites
1. Use the Mission-2 FULL ZIP as the source tree.
2. Apply Supabase migrations through **115** to an approved staging/QA project.
3. Create `.env.qa` from the existing QA example/guidance with staging credentials and test users.
4. Set `QA_MODE=staging` and `QA_ALLOW_MUTATION=true`.
5. Restore dependencies from the committed `package-lock.json`.
6. Run the normal local build/type/lint gate before browser QA.

## Recommended command
```bash
npm run qa:mission2
```

For visual observation:
```bash
QA_M2_HEADED=true npm run qa:mission2
```

For a slower project:
```bash
QA_USER_PACE_MS=1000 QA_CRAWL_PACE_MS=1000 npm run qa:mission2
```

## Expected execution
The runner is one-worker serial. It first runs the full Mission-1 fresh-seed/idempotency proof, then the normal-user journeys, role crawls, isolation test and mobile test.

Do not rerun by repeatedly clicking if the first run reports an error. Inspect:
- `qa-results/mission2/SUMMARY.md`
- `qa-results/mission2/runtime-issues.ndjson`
- `qa-results/BUG-REPORT.md`
- `qa-results/test-failures.json`
- `qa-results/html/`
- Playwright traces/screenshots/videos under `qa-results/artifacts/`
- launch seed report JSON generated by the UI when the Mission-1 seed gate fails

## Triage rule
For every real defect:
1. identify the exact user journey;
2. identify the failed HTTP/RPC/Storage/database contract;
3. fix root cause;
4. keep/add a deterministic assertion for that exact defect;
5. rerun the smallest affected spec;
6. rerun `npm run qa:mission2` before closing Mission 2.

Expected authorization denials are allowed only when explicitly declared by the test. Do not blanket-ignore 400/401/403/404/409/422 responses.

## Useful targeted commands
```bash
npm run qa:mission2:mission1-retest
npm run qa:mission2:desktop
npm run qa:mission2:mobile
npm run validate:mission2
```

## Go condition
The runtime result must be `MISSION2_CERTIFIED`, Mission-1 seed retest must pass before the broader journey evidence is accepted, and no unexplained P0/P1/P2 user-flow defect may remain.
