# Housing Society Founder Pilot — Admin Guide

## Purpose
Use HS-6 to prove that the housing-society vertical works as a repeatable product, not merely as a founder demo.

## Pilot sequence
1. **Pilot A — Internal demo:** synthetic 50–100-unit society; verify end-to-end flows without real resident data.
2. **Pilot B — 20–50 real units:** import one wing/tower where practical; recruit committee operators and resident champions.
3. **Pilot C — Full society:** import all units/residents and operate notices, complaints, maintenance visibility and the broader society workflows.
4. **Pilot D — Second society:** repeat onboarding without founder-specific code or manual database patches. This is the commercialization proof.

## Start a pilot
Open **Manage Society → Pilot readiness & commercialization evidence**. Select phase, target units, cohort and notes. Do not hard-code pricing or mutate historical evidence to make readiness look stronger.

## Weekly checkpoint
Record:
- admin hours saved per week;
- operations still happening only on WhatsApp/spreadsheets;
- committee willingness to pay;
- renewal intent;
- repeatability of onboarding;
- whether founder-specific code/manual patching was required;
- the most important friction and next action.

## Objective evidence
HS-6 derives evidence from existing product records: mapped imports, represented/claimed units, weekly active units, notice readership, complaint resolution, maintenance cycles, meetings and security/compliance/asset operations.

## Pricing experiments
Test one hypothesis at a time: per-unit/month, annual society fee, base + paid modules, or setup/migration fee. Record the amount and committee response. `Untested` is valid; pricing is evidence, not configuration truth.

## Exit criteria
Do not call the vertical commercial-ready merely because the founder's society works. Pilot D should onboard a second society using the same code, migrations, mapping kit and guides.
